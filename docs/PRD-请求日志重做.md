# 请求日志页

2026-10-11：参考 [magpie](https://github.com/yetone/magpie) 的请求列表重做现有“运行日志”页；保留应用的 WPF 控件、主题、字体和导航。日常请求默认按一行一条展示，准备、保活和系统启停放在“运行事件”。

## 布局与交互

```text
+----------------------------------------------------------------+
| 客户端                             实时跟随 [导出] [更多操作]   |
| [请求日志] [运行事件]                    日期 [...] [今天]       |
| [全部][失败][重试][处理中]              搜索 [...]               |
| [仅当前客户端]      新请求数量 / 已暂停跟随         [回到最新]   |
| 时间 / 客户端 | 模型 / 供应商 | 用量 / 费用 | 耗时 | 结果       |
| 展开：完整编号、请求与模型信息、用量明细、时间、错误原因         |
|       [复制编号] [查看请求诊断] [相关运行日志]                    |
| 显示数 / 总数                           [较新] 第 N 页 [较早]   |
+----------------------------------------------------------------+
```

请求按开始时间倒序显示，每页 100 条，支持日期、当前客户端、模型/供应商/完整编号搜索以及失败、重试、处理中筛选。“失败”也包含客户端交付中断。默认同时显示两类客户端，顶部客户端选择配合“仅当前客户端”使用。

运行事件按时间倒序显示，每页 200 条，保留来源和级别筛选、任务跳转、复制原文、完整编号复制、诊断跳转与全量导出。原始模型和思考强度对照在展开后显示，并保留不一致字段的颜色和字重。“更多操作”提供刷新、打开目录和运行事件清空显示；清空显示不删除磁盘记录。

页面使用深浅主题资源，不增加进场动画。页面宽度小于 620 时隐藏单独耗时列，展开详情仍显示完整时间信息；列表表头与内容对齐，滚动条有独立留白。关闭导航宿主对整页的额外滚动包装，由请求和事件列表独立滚动，分页始终保持在窗口内。

## 数据口径

请求列表读取诊断摘要，可查含今天 7 天。请求结果、重试次数、出站目标、首内容等待、总耗时和交付状态使用诊断记录；运行事件保留天数仍由原设置控制（1–3650 天，默认 7 天）。准备和保活不混入日常请求。

每页按完整请求编号查询统计用量，从请求开始日期到今天寻找同通道最新记录，覆盖跨日和跨月完成；不同通道的同名编号不合并，无法确定归属时保留缺失。查询利用现有主键索引筛选编号，再读取命中的统计正文；表结构、原数据和迁移归档保持。每日诊断复用现有增量缓存，统计只解析当前页命中的记录。

输入、缓存读取、缓存写入、输出和思考口径复用统计页；思考已包含在输出中。行内输入显示输入总量，详情显示各部分。费用使用响应模型优先、出站模型兜底，按统计页公开价或自定义单价估算，单位美元；`≈` 为估算，`≥` 为已知部分下限，缺失值显示 `—`。首字表示首内容等待。记录损坏、读取失败和诊断不完整明确提示。

导出保存当前日期全部筛选页的请求为 CSV，包含完整编号、精确用量、价格下限标志、HTTP 状态、交付和时间；缺失数值留空。字段正确转义逗号、引号和换行，并防止电子表格把文本当公式执行；写入完成后替换目标文件。运行事件仍导出为原文日志。

## 刷新与阅读位置

后台通知按 750 毫秒合并，离开页面停止订阅和刷新。现有行按稳定身份复用，只通知发生变化的字段；自动刷新不清空并重建整表。

滚动、选中、展开或翻页后暂停跟随，保持当时的成员、顺序、分页和阅读位置；已有请求可继续更新结果及用量，新请求仅显示数量提示。展开内容变高时按可见行位置恢复阅读位置，用户的滚轮或键盘操作优先。只有“回到最新”、重新开启实时跟随或“今天”会恢复跟随，没有定时自动恢复。更改筛选重新查询，过期的后台结果被取消。
