## 0. Context

- 重构前（2026-09-28）：RetryProxy 的“服务商”只有名称和地址，Key 由客户端自带、代理原样透传。换供应商或换 Key 要改 Claude Code / Codex 的配置文件并重开客户端，或者依赖别的工具；当前普通通道行为已由 §4.2、§7 的 2026-10-01 决策取代。
- 一键准备的 Key 手填在任务里，同一站点的多个 Key 要逐个建任务；准备好的 Key 和实际使用之间没有联系。
- 目标：RetryProxy 独立完成 Claude Code / Codex 的供应商与多 Key 管理。切换即时生效，准备与保活让 Key 随时可切。产品定位是完全替代 cc-switch 的供应商管理，但不导入、不兼容、也不检测 cc-switch。

## 1. 范围

包含：
- 供应商与多 Key 管理
- 切换即时生效，在途请求改投
- 客户端接管与直连恢复，首次使用向导
- 一键准备支持多 Key，状态回显，重启后自动恢复
- 托盘快速切换
- 界面重组

不包含：
- cc-switch 的导入、检测、共存处理；仅参考其热切换行为，不集成其程序或配置（2026-10-01 调整）
- 自动换 Key：额度不足、认证失败、限流时自动切到别的 Key（2026-09-28 取消，策略不好做好）
- MCP、提示词、技能；Claude Code 与 Codex 以外的客户端
- 通用配置片段、多地址测速、跨供应商故障转移、供应商预设模板
- 云同步、导入导出、深链接
- 按金额统计成本
- 官方账号登录（OAuth）型供应商
- Key 加密存储
- 余额查询（2026-10-03 移除：各供应商接口不统一，实际不可用）

### 2.1 产品行为

| # | 事项 | 决策 |

| P1 | 切换生效方式 | 热切换 = 已进入普通本机通道的请求立即使用当前 Key，无需为每次换供应商重开客户端。接管仍向客户端配置写本机地址和本地口令；普通通道无论收到旧密钥、错误口令或无凭据，都注入当前 Key 的地址、密钥和模型。首次接管、改端口或恢复直连后，两种客户端已打开的旧窗口均应重开；未进入本机通道的窗口不在热切换范围内。模型设置变化才同步客户端模型字段，模型菜单等显示以重开后的配置为准（2026-10-01 陛下确认，取代原“只对本地口令注入”和“Claude 自动重读即可生效”的约定） |

## 3. 术语

- 客户端 = Claude Code 或 Codex。
- 通道 = 某个客户端的本机端口，加上重试、超时、保活参数。
- 供应商 = 一个上游站点，属于某一个客户端。包含：名称、接口地址、认证方式（仅 Claude）、模型设置、官网、备注、Key 列表。
- Key = 供应商下的一个 API Key。包含：名称（如 主号、PLUS）、密钥、可选的模型覆盖、备注。
- 当前 Key = 某客户端此刻使用的"供应商 · Key"。
- 接管 = 把客户端配置改成指向本机通道端口，并用本地口令代替真实 Key。
- 直连 = 把客户端配置改回当前 Key 的真实地址和密钥，不经过本软件。
- 本地口令 = 每条通道随机生成的 32 位十六进制串，接管时写进客户端配置，用于识别本软件管理的配置，普通通道不以它作为注入当前 Key 的前提；后台独立准备代理仍要求正确口令（2026-10-01 陛下确认）。
- 热切换 = 客户端请求已进入普通本机通道后，由代理按当前供应商与 Key 转发，无需客户端重新读取地址或密钥；直接请求外部地址的窗口不受本机通道切换控制（2026-10-01 调整）。
- 已准备 = 该 Key 的一键准备任务已经成功，进入"独立保活"阶段。

## 4. 功能需求

### 4.1 供应商与 Key

- 列表：按客户端分开；卡片可拖动排序，Key 可在卡内拖动排序。
- 操作：供应商可新增、编辑、复制（名称加"副本"，插在原卡下方）、删除；Key 可新增、编辑、复制密钥、删除。
- 新增供应商时至少要有 1 个 Key，第一个 Key 的名称默认为"默认"。
- 删除限制：
  - 当前 Key，以及含当前 Key 的供应商，不能删除，提示先切到别的 Key。
  - 删除 Key 时，先停止它的准备任务，等状态变为已停止后再一并删除；删除前需要确认。供应商抽屉内删除 Key 在保存时执行同一联动；等待停止期间禁止相关任务新启动或重绑，供应商与准备任务一次原子保存，失败保留两者配置（任务维持已停止），不出现只删一半（2026-09-30 调整）。
  - 每个供应商至少保留 1 个 Key；删除最后一个 Key 时提示改为删除供应商。
- 名称规则：供应商名称在同一客户端内唯一，Key 名称在同一供应商内唯一。
- 「获取模型」：复用 `Core\Workspace\ProviderModelFetcher.FetchAsync`，用第一个 Key 请求，结果填进模型下拉框。
- 校验文案用中文，沿用现有风格。

### 4.2 切换

- 入口：供应商页 Key 行的「切换」、托盘菜单、「撤销」。M3 已接入供应商卡片、5 秒撤销和动态托盘；统一调用 `ProxyWorkspace.SwitchKey`（2026-09-29 调整）。
- 生效时间：从点击开始，之后的每一次尝试都读取新快照（地址、认证方式、Key、模型映射），通道不重启。普通通道统一使用当前 Key，入站携带旧真实 Key、错误口令或没有凭据均按同一规则处理，旧密钥不外发；当前无 Key 时本地返回 HTTP 403 `no_provider_key`（2026-10-01 陛下确认）。
- 在途请求（P2）：普通通道凡是还没有写给客户端任何字节的请求，都取消当前尝试和退避等待，立即用新 Key 重发；已开始输出的请求不受影响。改投不占重试次数，请求的总等待仍从开始时算起；只改参数（同一个 Key）时，正在进行的等待照常走完，下一次尝试再用新参数。携带旧密钥、错误口令或无凭据的请求同样适用，取代原“客户端自带凭据不改投”的约定（2026-10-01 陛下确认）。
- 客户端配置：地址和本地口令不动。只有模型设置变化时，才更新模型相关字段（见 §6.2）；失败不记为同步成功，按 §4.4 的有界事件重试补齐。
- 多窗口边界：已经进入本机通道的窗口共同跟随切换；首次接管、改端口或恢复直连后，两种客户端原已打开的窗口均应重开。进程保留外部地址，或使用环境变量、项目配置、独立配置目录绕过本机通道时，本软件不能替它改变请求去向（2026-10-01 调整）。
- 保活：本通道的保活会话重置，下一轮用新 Key 重新建立会话。通道未运行时切换同样丢弃旧会话（2026-09-29 调整）。
- 日志：沿用现有前缀规则 `[来源][通道][行为]`，示例：`[通道代理][Claude Code] 已切换：Any · 主号 → Any · 群号，2 个未输出的请求改用新 Key 重发`。每个改投的请求另记一行：`[编号] 已切换到 Any · 群号，本请求尚未向客户端输出，立即改用新 Key 重发（不计入重试次数）`；普通通道请求完成行统一写明实际使用的“供应商 · Key”，不再按客户端原凭据标记“客户端凭据”（2026-10-01 调整）。
- 撤销：提示条上的「撤销」等同于切回上一个 Key，走同一套流程。

### 4.3 自动换 Key（已取消，2026-09-28）

不做。当前 Key 出现额度不足、认证失败、限流等错误时，按通道原有规则重试或返回给客户端，是否换 Key 由用户在供应商页或托盘手动决定。2026-10-01 陛下确认：等待生成阶段收到明确限流错误、尚未向客户端转发时，也按通道的重试与等待上限重试；已开始转发时保持不重试，详见《PRD-CSharp-重构》§6.3。此规则不增加自动换 Key。

### 4.4 客户端接管与直连恢复

- 配置文件位置：
  - Claude Code：`%CLAUDE_CONFIG_DIR%\settings.json`，未设置时为 `~\.claude\settings.json`。
  - Codex：`%CODEX_HOME%\config.toml`，未设置时为 `~\.codex\config.toml`。
  - `LocalProviderCredentials` 已改为复用配置编辑器，识别 `CLAUDE_CONFIG_DIR`；Codex 优先读取所选供应商段内的 token，仅缺少时读取 `auth.json`（2026-09-30）。
- 接管前提：该客户端的当前供应商至少有 1 个 Key；否则提示先添加 Key（向导第 1 步会自动补上）。
- 接管 Claude Code：
  - 在 `env` 里合并写入：`ANTHROPIC_BASE_URL=http://127.0.0.1:{端口}`、`ANTHROPIC_AUTH_TOKEN={本地口令}`。
  - 删除 `ANTHROPIC_API_KEY` 和 `apiKeyHelper`，原值在备份里。
  - 模型变量：`ANTHROPIC_MODEL` 写固定主模型标记 `retry-proxy-main`，`ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU,FABLE}_MODEL` 写固定官方角色名（软件内常量表，初始值为 `claude-opus-5`、`claude-sonnet-5`、`claude-haiku-4-5`、`claude-fable-5`）；按对应模型的 1M 设置决定是否加 `[1M]`；`*_MODEL_NAME` 写当前 Key 的真实模型名。`CLAUDE_CODE_SUBAGENT_MODEL` 如果存在，已识别角色写对应角色名，其余写主模型标记。未设置有效目标模型时保留客户端真实模型；若原值是上次接管写入的标记，先从对应 `*_MODEL_NAME` 恢复真实模型并保留原 1M 设置；主模型标记没有可恢复名称时移除该项，交回客户端默认模型（2026-09-30 调整）。主模型与四角色保持独立，即使四角色全部单独设置，普通对话仍使用主模型；主模型标记不含角色关键字，代理沿用主模型回退规则改写（2026-09-29 陛下确认）。
  - 其余键保持原样。
- 接管 Codex：
  - 沿用 config.toml 里现有的 `model_provider` 名称，因为 Codex 的历史会话按这个名称分组。
  - 如果没写 `model_provider`，或它是内置的 `openai`，就新建 `[model_providers.retry_proxy]` 并改用它；向导里提示"历史会话列表会按新名称分组"。
  - 在该段写入：`base_url="http://127.0.0.1:{端口}/v1"`、`wire_api="responses"`、`experimental_bearer_token="{本地口令}"`。
  - 顶层的 `model`、`model_context_window`、`model_auto_compact_token_limit` 按当前 Key 写；未设置的项不动。
  - 其他段落、注释、顺序都保留，`auth.json` 不动。
- 直连（P11，以及设置页的「取消接管」）：
  - 把当前 Key 的真实地址、密钥、模型写回客户端配置。Claude 按认证方式写 `ANTHROPIC_AUTH_TOKEN` 或 `ANTHROPIC_API_KEY`；Codex 写 `experimental_bearer_token`，地址按 §6.1 规则补 `/v1`。
  - 「取消接管」是持久选择：之后启动不再自动接管，直到用户重新点「接管」。
  - 生效：首次接管、改端口或恢复直连后，Claude Code 与 Codex 已打开的旧窗口均应重开；不再承诺 Claude Code 自动重读配置就能让所有运行窗口采用新地址（2026-10-01 调整）。
- 写入安全：
  - 首次接管前，把原文件备份到 `User\backup\client\{客户端}\{yyyyMMdd-HHmmss}\`。
  - 用临时文件加替换的方式写入，失败就回滚并提示。
  - 写入前比对上次写入时的哈希；如果文件被客户端或用户改过，就重新读取，只改本软件负责的键。
  - Windows 共享/锁冲突（错误码 32/33）最多重试 20 次，每次间隔 25 ms；替换阶段的 `File.Replace` 错误码 1175 同样有界重试。每次重试重新检查原文件哈希与禁写状态；1176/1177 不盲目重试，权限、磁盘与内容冲突按失败处理。安全日志仅记录阶段和 HRESULT（Windows 错误码），不记录路径、文件内容或原始异常文本（2026-10-01 修复）。
  - 协调层仅在写入与状态保存均成功后标记同步完成。失败后，同一目标在后续既有事件中最多再试 2 次，不新增定时器、不反复通知；重试前仍检查外部改动，用户已改往其他地址或 Key 时保留原文件（2026-10-01 修复）。
- 检测：启动时和窗口激活时，检查客户端配置是否仍然指向本通道并带着本地口令；不符合时，状态条显示“配置被改动”并提供「重新接管」。自动启停、停机切 Key、异常恢复及退出只修改仍匹配本软件口令、上次写入内容或上次直连凭据的文件；外部改往其他地址或 Key 时保留用户修改，不自动接回（2026-09-30 调整）。该状态只确认配置文件，不保证所有已打开窗口使用该配置；普通通道是否注入 Key 不依赖该状态（2026-10-01 调整）。
- 改端口：通道停止、保存后重新启动，并更新已接管客户端的地址；两种客户端已打开的旧窗口均应重开（2026-10-01 调整）。

### 4.5 首次使用向导（U16）

- 触发时机：首次运行，或升级到带 M4 的版本后首次打开。用 `commonConfig.clientSetupCompleted` 独立记录完成或跳过，保证已用过 M3 的用户也能进入；托盘隐藏启动时，首次显示窗口再进入。每一步都可跳过，设置页可重新打开（2026-09-30 调整）。
- 第 1 步，保存现有配置（P12）。读取两个客户端当前的地址、Key、模型：
  - 读取来源：Claude 取 `env.ANTHROPIC_BASE_URL`，Key 依次取 `ANTHROPIC_AUTH_TOKEN`（Bearer）、`ANTHROPIC_API_KEY`（x-api-key），模型取 `ANTHROPIC_MODEL` 与各角色变量；Codex 取当前 `model_provider` 段的 `base_url`，Key 依次取该段 `experimental_bearer_token`、`auth.json` 的 `OPENAI_API_KEY`，模型取顶层 `model`、`model_context_window`、`model_auto_compact_token_limit`。
  - 指向外部地址：预览"将存为供应商"，名称可以改，确认后新建供应商和 Key。
  - 已经指向本软件端口（旧用法：客户端带着真实 Key 连本机端口）：把其中的 Key 挂到该通道当前供应商下，名称为"默认"。
  - 指向本机其他端口（`127.0.0.1` / `localhost` 上的别的程序）：说明"当前指向本机另一个程序，读不到真实 Key"，不自动保存，改为引导手动新增供应商。
  - 没有地址或 Key（官方登录）：跳过，并说明"官方登录不支持"。
- 第 2 步，接管：列出要修改的文件和备份位置，确认后执行 §4.4。
- 第 3 步，完成：显示两个客户端的当前 Key 和本机地址，并说明首次接管后两种客户端已打开的旧窗口均应重开；已进入本机通道的窗口随后可共同热切换，未经过本机通道的窗口不受控制（2026-10-01 调整）。
- 每一步都可以跳过；跳过的事项之后可以在状态条或设置页继续完成。

### 4.6 余额查询（2026-10-03 移除）

- 原设计（2026-09-30）：每个 Key 单独查询，方式五选一（自动识别 / 通用用量接口 / 余额接口 / OpenAI 兼容账单接口 / 不查询），结果显示在 Key 行（U9）与托盘（U15）。
- 移除原因：各供应商接口不统一，实际不可用。

### 4.7 一键准备

- 来源（P8）：
  - 跟随当前：开始时取本客户端的当前 Key，替代原来的"使用本机客户端当前供应商"（接管后配置文件里只有本地口令，不能再从文件读）。
  - 从列表选择：先选供应商，再勾选一个或多个 Key，一次创建多项任务，每个 Key 一项，共用模型、思考强度、保活间隔。
  - 手动填写：保持现状。
- 每个 Key 最多只能有一项管理来源任务；已有任务的 Key 在勾选列表里显示“已有任务”，不能再勾选（编辑该任务自身时除外）。手动填写不按密钥内容推断归属（2026-09-30 调整）。

- 批量创建先全部校验，再一次保存，然后启动各项服务；保存失败时不创建或启动任何任务。退出时先完成普通通道的保存与停止，再保存准备任务的运行意图和最终统计并释放服务，防止后续保存把任务列表覆盖为空（2026-09-30 调整）。

  - 模型：该 Key 的有效模型。
  - 思考强度：默认（沿用客户端）。
  - 保活间隔：5 分钟。
- Key 行状态：未准备 / 准备中 mm:ss / 已准备 · 下次 mm:ss / 准备失败（悬停看原因）。
- 重启恢复（P10）：退出时记录每项任务是否在运行，下次启动后自动开始这些任务；用户手动停止的任务不会自己恢复。
- 与切换的关系：切换到某个 Key 不会停止它的准备任务；准备会话与用户会话相互独立，不承诺用户请求一定命中准备会话的缓存（2026-09-30 调整）。
- 每日轮次统计按本机日期保存，累计已结束的成功、失败、中断轮次；悬停显示今日轮次和成功数，重启保留同一天计数，跨日归零（2026-09-30 调整）。

## 6. 地址与模型规则

### 6.1 地址拼接

- Claude：
  - 客户端地址：`http://127.0.0.1:{端口}`，客户端请求 `/v1/messages` 等路径。
  - 上游地址：供应商地址原样 + 入站路径 + 查询串。例：`https://anyrouter.top` → `https://anyrouter.top/v1/messages`。
- Codex：
  - 客户端地址：`http://127.0.0.1:{端口}/v1`，客户端请求 `/v1/responses`。
  - 上游地址：供应商地址（没有路径时按 `{地址}/v1` 处理）+ 入站路径去掉开头的 `/v1` + 查询串。例：

## 7. 安全

- 普通本机通道（2026-10-01 陛下确认，完全跟随 CC Switch 的路由行为）：
  - 凡是进入普通通道并通过 Host / Origin 校验的转发请求，统一使用当前供应商的当前 Key；携带旧真实 Key、错误口令或无凭据均不影响注入。
  - 入站鉴权替换为当前 Key 的认证头，客户端原密钥与本地口令不外发；取代原“其他凭据原样透传”的约定。
  - 当前供应商没有 Key 时，在本地直接返回明确错误“当前供应商没有 Key”：HTTP 403，错误类型 `no_provider_key`，提示先为该供应商添加 Key；不使用客户端自带密钥兜底。
  - 本机其他程序也可以通过普通通道使用当前 Key；该边界已向用户说明并确认，Host / Origin 校验不能区分不同本机程序。
- 本地口令与准备代理：
  - 每条通道仍随机生成本地口令，保存在 config.json，接管时写进客户端配置，用于识别本软件管理的配置；普通通道不以匹配口令作为转发门槛（2026-10-01 调整）。
  - 后台独立准备代理仍严格校验其本地口令，错误口令或无凭据请求本地拒绝；通过后只使用该准备任务的 Key，不随普通通道切换（2026-10-01 确认保留）。
- 访问限制：只接受 Host 为 `127.0.0.1` / `localhost` 的请求，拒绝带 `Origin` 头的请求（防止网页通过 DNS 重绑定借用端口）。健康检查同样受限；拒绝时返回 HTTP 403，日志每分钟最多一条，不记录请求里的原值（2026-09-29 调整，2026-10-01 保留）。
- 通道保活的 CLI：始终显式指向本通道并带上本地口令，是否接管都能经过本通道。当前供应商还没有 Key 时沿用本机 CLI 默认配置（2026-09-29 调整）。
- 明文 Key（P5）：`config.json`、`User\backup\` 下的各种备份、直连时写回的客户端配置都含明文 Key；设置页在备份目录旁加提示。
- 脱敏：
  - 日志、统计、异常报告、`/_retry/health` 中都不出现 Key 或本地口令。
  - 界面列表只显示 Key 前 4 位与末 4 位（U18，2026-09-29 调整）。
  - 保活 CLI 需要的密钥或本地口令写进会话工作目录里的设置文件再传路径，不出现在命令行上；工作目录在会话结束时删除（2026-09-29 调整）。

## 12. 验收标准

1. 迁移：以 dist 的真实配置结构迁移后，两条通道的 ID 不变，当日统计能继续累加；旧准备任务的来源映射正确。
2. 向导与接管：在临时的 `CLAUDE_CONFIG_DIR` / `CODEX_HOME` 下完成三步向导。
   - 原有地址和 Key 存成了供应商。
   - `settings.json`、`config.toml` 只有规定的键发生变化，备份存在；Codex 的 `model_provider` 名称没变。
   - 首次接管完成提示两种客户端原已打开窗口均应重开；配置文件写入成功不能替代每个窗口已经接入的证据（2026-10-01 调整）。
3. 直连恢复：退出软件后，客户端配置为当前 Key 的真实地址、密钥和模型；再次启动后自动接管。验证文件短暂占用／替换 1175 的有界重试、1176/1177 不盲重试、重试期间外部改动与禁写保护；协调层失败不标记成功，同目标后续事件最多再试 2 次，仍保留外部修改（2026-10-01 调整）。
4. 即时切换：用假上游 A、B 与多个独立客户端连接验证（2026-10-01 调整）。
   - 普通通道分别收到本地口令、旧真实 Key、错误口令和无凭据请求时，下一次尝试均打到 B，使用 B 的 Key、模型和地址；原密钥与口令不外发。
   - 上述各类请求正在退避或等待生成时立即改投 B；已经开始输出的请求留在 A。
   - 「撤销」能切回 A；多个已接入窗口共同跟随，未经过本机通道的请求不宣称受本软件切换控制。
5. 模型映射：
   - 普通通道的旧密钥、错误口令和无凭据请求同样适用：Claude 按角色映射，1M 头按目标角色删除（只删不加，见 §6.2），`count_tokens` 也会改写；Codex 请求有效的手选模型时不改写（2026-10-01 调整）。
   - 模型配置同步失败后能够由后续既有事件有界重试，不把失败当成已同步；两种客户端模型菜单等显示以重新打开后的配置为准。
6. 安全：
   - 普通通道统一注入当前 Key；当前无 Key 时，即使客户端带有真实 Key 也在本地返回 HTTP 403 `no_provider_key`。后台独立准备代理仍拒绝错误口令及无凭据请求（2026-10-01 调整）。
   - Host 非本机、或带 Origin 的请求被拒绝；普通通道允许本机其他程序使用当前 Key，按已确认的安全边界验收。
   - 日志和健康检查中不出现 Key 或口令；客户端配置失败诊断只含阶段及 HRESULT，不含路径、内容或原始异常文本。
7. 一键准备：
   - 一次勾选同一供应商的 3 个 Key，生成 3 项任务；供应商页状态同步。
   - 重启后，原本运行中的任务自动恢复。
   - 删除 Key 会联动停止并删除它的任务。
8. 余额查询（2026-10-03 移除，2026-10-04 发布）：界面不再有查询入口；含 balance_query 的旧配置可正常读取，保存后字段消失。
