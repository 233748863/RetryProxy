# PRD：RetryProxy 供应商与多 Key 管理（Claude Code / Codex）

版本 v0.2 草案　日期 2026-09-28
落盘位置：`D:\RetryProxy\docs\PRD-供应商管理.md`（UTF-8）。本文是活文档：每完成一个里程碑、每改一项决策，当轮就改到对应章节并标日期，§11 状态列记录进度（写法沿用《PRD-CSharp-重构》的里程碑表）。

## 0. Context

- 现状：RetryProxy 的"服务商"只有名称和地址，Key 由客户端自带、代理原样透传。换供应商或换 Key 要改 Claude Code / Codex 的配置文件并重开客户端，或者依赖别的工具。
- 一键准备的 Key 手填在任务里，同一站点的多个 Key 要逐个建任务；准备好的 Key 和实际使用之间没有联系。
- 目标：RetryProxy 独立完成 Claude Code / Codex 的供应商与多 Key 管理。切换即时生效，准备与保活让 Key 随时可切。产品定位是完全替代 cc-switch 的供应商管理，但不导入、不兼容、也不检测 cc-switch。

---

## 1. 范围

包含：
- 供应商与多 Key 管理
- 切换即时生效，在途请求改投
- 客户端接管与直连恢复，首次使用向导
- 余额查询
- 一键准备支持多 Key，状态回显，重启后自动恢复
- 托盘快速切换
- 界面重组

不包含：
- cc-switch 相关的一切：导入、检测、共存处理
- 自动换 Key：额度不足、认证失败、限流时自动切到别的 Key（2026-09-28 取消，策略不好做好）
- MCP、提示词、技能；Claude Code 与 Codex 以外的客户端
- 通用配置片段、多地址测速、跨供应商故障转移、供应商预设模板
- 云同步、导入导出、深链接
- 按金额统计成本
- 官方账号登录（OAuth）型供应商
- Key 加密存储

## 2. 已确认决策（2026-09-28）

### 2.1 产品行为

| # | 事项 | 决策 |
|---|---|---|
| P1 | 切换生效方式 | 立即生效，不用重开客户端。接管时往客户端配置写一次本机地址和本地口令，之后切换由代理注入新 Key 的地址、密钥和模型。只有新 Key 的模型设置与原来不同时，才同步客户端配置里的模型字段：Claude Code 会自动重读，Codex 下次打开生效 |
| P2 | 在途请求 | 切换时，尚未向客户端输出任何内容的请求立即中止当前尝试（包括退避等待、等待生成），改用新 Key 重发；已开始输出的请求在原 Key 上走完 |
| P3 | 通道 | 每个客户端一条通道：Claude Code 用 18081，Codex 用 18080。保留现有通道 ID（每日统计按它分目录），名称固定为客户端名 |
| P4 | 附加功能 | 只做余额查询 |
| P5 | Key 存储 | 明文保存在 `User\config.json` |
| P6 | 多 Key | 一个供应商挂多个 Key，切换时选到具体 Key |
| P7 | 多 Key 准备的用途 | 已准备的 Key 在供应商页可见，可一键切换；准备任务持续保活。原第三项"当前 Key 出问题时自动换 Key"已取消（2026-09-28） |
| P8 | 一键准备的供应商来源 | 三种：跟随当前 / 从列表选（可一次选多个 Key）/ 手动填写（保留） |
| P9 | 自动换 Key | 已取消（2026-09-28）：不做自动换 Key，切换只由用户手动完成；上游失败仍按通道原有重试规则处理 |
| P10 | 重启后的准备任务 | 上次退出时仍在运行的任务，启动后自动恢复 |
| P11 | 退出与停止 | 代理停止时（退出软件或手动停止），已接管的客户端自动改回直连当前 Key；代理再次启动时自动重新接管 |
| P12 | 接管前的原配置 | 客户端原有的地址和 Key 先存成供应商（向导里可预览、可改名），再接管 |

## 3. 术语

- 客户端 = Claude Code 或 Codex。
- 通道 = 某个客户端的本机端口，加上重试、超时、保活参数。
- 供应商 = 一个上游站点，属于某一个客户端。包含：名称、接口地址、认证方式（仅 Claude）、模型设置、官网、备注、余额查询方式、Key 列表。
- Key = 供应商下的一个 API Key。包含：名称（如 主号、PLUS）、密钥、可选的模型覆盖、备注。
- 当前 Key = 某客户端此刻使用的"供应商 · Key"。
- 接管 = 把客户端配置改成指向本机通道端口，并用本地口令代替真实 Key。
- 直连 = 把客户端配置改回当前 Key 的真实地址和密钥，不经过本软件。
- 本地口令 = 每条通道随机生成的 32 位十六进制串，接管时写进客户端配置。代理只对带本地口令的请求注入真实 Key。
- 已准备 = 该 Key 的一键准备任务已经成功，进入"独立保活"阶段。

## 4. 功能需求

### 4.1 供应商与 Key

- 列表：按客户端分开；卡片可拖动排序，Key 可在卡内拖动排序。
- 操作：供应商可新增、编辑、复制（名称加"副本"，插在原卡下方）、删除；Key 可新增、编辑、复制密钥、删除。
- 新增供应商时至少要有 1 个 Key，第一个 Key 的名称默认为"默认"。
- 删除限制：
  - 当前 Key，以及含当前 Key 的供应商，不能删除，提示先切到别的 Key。
  - 删除 Key 时，先停止它的准备任务，等状态变为已停止后再一并删除；删除前需要确认。
  - 每个供应商至少保留 1 个 Key；删除最后一个 Key 时提示改为删除供应商。
- 名称规则：供应商名称在同一客户端内唯一，Key 名称在同一供应商内唯一。
- 「获取模型」：复用 `Core\Workspace\ProviderModelFetcher.FetchAsync`，用第一个 Key 请求，结果填进模型下拉框。
- 校验文案用中文，沿用现有风格。

### 4.2 切换

- 入口：供应商页 Key 行的「切换」、托盘菜单、「撤销」。
- 生效时间：从点击开始，之后的每一次尝试都读取新快照（地址、认证方式、Key、模型映射），通道不重启。
- 在途请求（P2）：凡是还没有写给客户端任何字节的请求，都取消当前尝试和退避等待，立即用新 Key 重发；已开始输出的请求不受影响。
- 客户端配置：地址和本地口令不动。只有模型设置变化时，才更新模型相关字段（见 §6.2）。
- 保活：本通道的保活会话重置，下一轮用新 Key 重新建立会话。
- 日志：沿用现有前缀规则 `[来源][通道][行为]`，示例：`[通道代理][Claude Code] 已切换：Any · 主号 → Any · 群号，2 个未输出的请求改用新 Key 重发`。
- 撤销：提示条上的「撤销」等同于切回上一个 Key，走同一套流程。

### 4.3 自动换 Key（已取消，2026-09-28）

不做。当前 Key 出现额度不足、认证失败、限流等错误时，按通道原有规则重试或返回给客户端，是否换 Key 由用户在供应商页或托盘手动决定。

### 4.4 客户端接管与直连恢复

- 配置文件位置：
  - Claude Code：`%CLAUDE_CONFIG_DIR%\settings.json`，未设置时为 `~\.claude\settings.json`。
  - Codex：`%CODEX_HOME%\config.toml`，未设置时为 `~\.codex\config.toml`。
  - `LocalProviderCredentials` 目前不认 `CLAUDE_CONFIG_DIR`，要一并修正。
- 接管前提：该客户端的当前供应商至少有 1 个 Key；否则提示先添加 Key（向导第 1 步会自动补上）。
- 接管 Claude Code：
  - 在 `env` 里合并写入：`ANTHROPIC_BASE_URL=http://127.0.0.1:{端口}`、`ANTHROPIC_AUTH_TOKEN={本地口令}`。
  - 删除 `ANTHROPIC_API_KEY` 和 `apiKeyHelper`，原值在备份里。
  - 模型变量：`ANTHROPIC_MODEL` 和 `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU,FABLE}_MODEL` 写成固定的官方角色名（软件内常量表，初始值取本机现有配置里的 `claude-opus-5`、`claude-sonnet-5`、`claude-haiku-4-5`、`claude-fable-5`，随 Claude Code 版本更新）；按当前 Key 的 1M 设置决定是否加 `[1M]`；`*_MODEL_NAME` 写当前 Key 的真实模型名。`CLAUDE_CODE_SUBAGENT_MODEL` 如果存在，按角色改成对应的角色名。
  - 其余键保持原样。
- 接管 Codex：
  - 沿用 config.toml 里现有的 `model_provider` 名称，因为 Codex 的历史会话按这个名称分组。
  - 如果没写 `model_provider`，或它是内置的 `openai`，就新建 `[model_providers.retry_proxy]` 并改用它；向导里提示"历史会话列表会按新名称分组"。
  - 在该段写入：`base_url="http://127.0.0.1:{端口}/v1"`、`wire_api="responses"`、`experimental_bearer_token="{本地口令}"`。
  - 顶层的 `model`、`model_context_window`、`model_auto_compact_token_limit` 按当前 Key 写；未设置的项不动。
  - 其他段落、注释、顺序都保留，`auth.json` 不动。
- 直连（P11，以及设置页的「取消接管」）：
  - 把当前 Key 的真实地址、密钥、模型写回客户端配置。Claude 按认证方式写 `ANTHROPIC_AUTH_TOKEN` 或 `ANTHROPIC_API_KEY`；Codex 写 `experimental_bearer_token`，地址按 §6.1 规则补 `/v1`。
  - 「取消接管」是持久选择：之后启动不再自动接管，直到用户重新点「接管」。
  - 生效：Claude Code 会自动重读 `settings.json`；已打开的 Codex 会话仍连本机端口，需要重开 Codex。
- 写入安全：
  - 首次接管前，把原文件备份到 `User\backup\client\{客户端}\{yyyyMMdd-HHmmss}\`。
  - 用临时文件加替换的方式写入，失败就回滚并提示。
  - 写入前比对上次写入时的哈希；如果文件被客户端或用户改过，就重新读取，只改本软件负责的键。
- 检测：启动时和窗口激活时，检查客户端配置是否仍然指向本通道并带着本地口令；不是的话，状态条显示"配置被改动"并提供「重新接管」。
- 改端口：通道停止、保存后重新启动，并更新已接管客户端的地址；已打开的客户端会话需要重开。

### 4.5 首次使用向导（U16）

- 触发时机：首次运行，或从 schema 6 升级后第一次打开。
- 第 1 步，保存现有配置（P12）。读取两个客户端当前的地址、Key、模型：
  - 读取来源：Claude 取 `env.ANTHROPIC_BASE_URL`，Key 依次取 `ANTHROPIC_AUTH_TOKEN`（Bearer）、`ANTHROPIC_API_KEY`（x-api-key），模型取 `ANTHROPIC_MODEL` 与各角色变量；Codex 取当前 `model_provider` 段的 `base_url`，Key 依次取该段 `experimental_bearer_token`、`auth.json` 的 `OPENAI_API_KEY`，模型取顶层 `model`、`model_context_window`、`model_auto_compact_token_limit`。
  - 指向外部地址：预览"将存为供应商"，名称可以改，确认后新建供应商和 Key。
  - 已经指向本软件端口（旧用法：客户端带着真实 Key 连本机端口）：把其中的 Key 挂到该通道当前供应商下，名称为"默认"。
  - 指向本机其他端口（`127.0.0.1` / `localhost` 上的别的程序）：说明"当前指向本机另一个程序，读不到真实 Key"，不自动保存，改为引导手动新增供应商。
  - 没有地址或 Key（官方登录）：跳过，并说明"官方登录不支持"。
- 第 2 步，接管：列出要修改的文件和备份位置，确认后执行 §4.4。
- 第 3 步，完成：显示两个客户端的当前 Key 和本机地址。
- 每一步都可以跳过；跳过的事项之后可以在状态条或设置页继续完成。

### 4.6 余额查询

- 每个 Key 单独查询。结果显示在 Key 行（U9）：余额加单位；悬停显示"查询于 HH:mm"；查询失败显示"—"，悬停看原因（不含 Key）。
- 查询方式在供应商层设置，四选一：
  - 自动识别：新增供应商时的默认值。依次试下面三种接口，记住能用的那一种。
  - 通用用量接口：`GET {查询地址}/v1/usage`。依次取 `remaining`、`quota.remaining`、`balance`；单位依次取 `unit`、`quota.unit`，都没有时为 USD。
  - 余额接口：`GET {查询地址}/user/balance`。如果有 `data` 对象就在它里面取；依次取 `remaining`、`balance`；单位依次取 `unit`、`currency`，都没有时为 CNY。
  - OpenAI 兼容账单接口（one-api / new-api 系中转站通用）：余额 = `GET {查询地址}/v1/dashboard/billing/subscription` 的 `hard_limit_usd` − `GET {查询地址}/v1/dashboard/billing/usage` 的 `total_usage` ÷ 100，单位 USD；`hard_limit_usd` ≥ 100000000 时显示"不限额"。
  - 不查询。
- 请求头：各接口都带 `Authorization: Bearer {Key}` 和 `User-Agent: RetryProxy/{版本}`。
- 失效判断：`is_active` 或 `isActive` 为 false 时，显示"Key 已失效"（标红）。
- 查询地址 = 供应商地址去掉末尾的 `/v1`。
- 刷新时机：
  - 打开供应商页时，刷新超过 5 分钟未更新的结果。
  - 卡片上的「刷新余额」手动刷新。
  - 当前 Key 和已准备的 Key 每 30 分钟在后台刷新一次。
- 限制：同时最多查 4 个，单次超时 10 秒，出网按系统代理规则。

### 4.7 一键准备

- 来源（P8）：
  - 跟随当前：开始时取本客户端的当前 Key，替代原来的"使用本机客户端当前供应商"（接管后配置文件里只有本地口令，不能再从文件读）。
  - 从列表选择：先选供应商，再勾选一个或多个 Key，一次创建多项任务，每个 Key 一项，共用模型、思考强度、保活间隔。
  - 手动填写：保持现状。
- 每个 Key 最多只能有一项任务；已有任务的 Key 在勾选列表里显示"已有任务"，不能再勾选。
- 地址、Key、模型在每次开始时按"供应商 ID + Key ID"解析。修改供应商后，下次开始才生效。
- 从供应商页发起（U10）：Key 行「准备」、卡片「准备全部 Key」，点击立即开始，参数默认为：
  - 模型：该 Key 的有效模型。
  - 思考强度：默认（沿用客户端）。
  - 保活间隔：5 分钟。
- Key 行状态：未准备 / 准备中 mm:ss / 已准备 · 下次 mm:ss / 准备失败（悬停看原因）。
- 重启恢复（P10）：退出时记录每项任务是否在运行，下次启动后自动开始这些任务；用户手动停止的任务不会自己恢复。
- 与切换的关系：切换到某个 Key 不会停止它的准备任务；已准备的 Key 切过去后，客户端的下一个请求直接命中已建立上下文的会话。
- 旧任务迁移：`providerSource=local` 改为"跟随当前"；`custom` 不变。

### 4.8 托盘（U15）

- 菜单结构：显示窗口 / `Claude Code：{当前供应商 · Key}` ▸ / `Codex：{当前供应商 · Key}` ▸ / 退出。
- 子菜单：平铺全部"供应商 · Key"，每项带余额，当前项打勾，点击即切换。

### 5.2 供应商页

## 6. 地址与模型规则

### 6.1 地址拼接

- Claude：
  - 客户端地址：`http://127.0.0.1:{端口}`，客户端请求 `/v1/messages` 等路径。
  - 上游地址：供应商地址原样 + 入站路径 + 查询串。例：`https://anyrouter.top` → `https://anyrouter.top/v1/messages`。
- Codex：
  - 客户端地址：`http://127.0.0.1:{端口}/v1`，客户端请求 `/v1/responses`。
  - 上游地址：供应商地址（没有路径时按 `{地址}/v1` 处理）+ 入站路径去掉开头的 `/v1` + 查询串。例：
    - `https://anyrouter.top` → `https://anyrouter.top/v1/responses`
    - `https://x666.me/v1` → `https://x666.me/v1/responses`
    - `https://new.sharedchat.cc/codex` → `https://new.sharedchat.cc/codex/responses`
- 余额查询：用供应商地址去掉末尾 `/v1` 后的查询地址（§4.6）。
- 现有约定要一起调整：`CliSession.cs` 追加 `/v1`、`PreparationWorkspace.cs` 去掉 `/v1`，改为统一使用上面的规则。

### 6.2 模型映射

- Claude：
  - 接管后，客户端配置里写的是固定的官方角色名（§4.4）。代理按请求模型名里的关键字 opus / sonnet / haiku / fable，映射到当前 Key 对应角色的模型；没有单独指定的角色用主模型；关键字都不匹配时，也用主模型。
  - 1M 处理：Claude Code 发请求时会去掉 `[1M]` 后缀，改为带 `anthropic-beta: context-1m-*` 头。目标角色没有勾选 1M 时，删掉这个头。
  - 改写范围：所有带顶层 `model` 字段的 JSON POST，包括 `/v1/messages/count_tokens`。
- Codex：只有当请求的模型不在当前供应商的已知模型列表里时，才改写成当前 Key 的模型。已知模型列表包括供应商模型、各 Key 的覆盖模型、最近一次「获取模型」的结果。用户在 Codex 里手选的有效模型保持不变。
- 改写方式：按字节替换顶层 `model` 字符串（用 JSON 读取器定位），不重新序列化，与 D10 原则一致。日志记录改写前后的模型名。
- 客户端配置同步（P1）：切换后如果模型设置有变化，只更新模型相关字段。
  - Claude：`*_MODEL_NAME` 和各角色的 `[1M]`。
  - Codex：`model`、上下文窗口、自动压缩阈值。
  - 地址和本地口令保持不变。

## 7. 安全

- 本地口令：
  - 每条通道随机生成，保存在 config.json，接管时写进客户端配置。
  - 代理只对带本地口令的请求注入真实 Key；口令绝不外发。
  - 带其他凭据的请求（未接管的旧用法）原样透传，不注入。
  - 带本地口令、但当前供应商没有 Key 时，在本地直接返回明确错误"当前供应商没有 Key"。
- 访问限制：只接受 Host 为 `127.0.0.1` / `localhost` 的请求，拒绝带 `Origin` 头的请求（防止网页通过 DNS 重绑定借用端口）。
- 通道保活的 CLI：始终显式指向本通道并带上本地口令，是否接管都能经过本通道。
- 明文 Key（P5）：`config.json`、`User\backup\` 下的各种备份、直连时写回的客户端配置都含明文 Key；设置页在备份目录旁加提示。
- 脱敏：
  - 日志、统计、异常报告、`/_retry/health` 中都不出现 Key 或本地口令。
  - 余额查询的错误信息按 Key 值精确打码。
  - 界面列表只显示 Key 末 4 位。

## 8. 数据与配置

- `User\config.json` 的 `proxy` 节点升级到 schema 7，写法仍为 snake_case、固定键序：
  - `providers[]`：`id`、`client_type`、`name`、`base_url`、`auth_mode`、`models`、`website_url`、`notes`、`balance_query`、`sort_index`，以及 `keys[]`。
  - `keys[]`：`id`、`name`、`api_key`、`model_override`、`notes`。
  - `models`：
    - Claude：主模型、主模型的 1M 标记，以及 Opus / Sonnet / Haiku / Fable 四个角色各自的模型与 1M 标记。
    - Codex：模型、上下文窗口、自动压缩阈值。
  - `routes[]`：每个客户端一条。保留原有 ID 和参数字段，去掉 `provider_name`，新增 `current_provider_id`、`current_key_id`、`local_token`。
  - `client_takeover`：每个客户端一项，包括 `enabled`（用户选择）、`config_path`、`backup_path`、`last_written_hash`。
- `preparations[]`：保持 camelCase，新增 `providerId`、`keyId`、`wasRunning`；`providerSource` 取值为 `current` / `list` / `custom`。
- 从 schema 6 迁移：
  - 迁移前把 `config.json` 备份到 `User\backup\`。
  - 旧服务商按引用它的通道的客户端类型，拆成对应客户端的供应商；这些供应商没有 Key，其中的 Key 由向导第 1 步补上。被丢弃的通道引用过的服务商也照样拆分保留；没有任何通道引用的服务商，两个客户端各保留一份，避免丢失（2026-09-29 调整）。
  - 每种客户端保留一条通道：优先当前选中的通道，其次列表中的第一条。保留 ID，改名为客户端名；多余的通道写日志后丢弃。缺某个客户端的通道时补建一条（Codex 优先 18080、Claude Code 优先 18081，被占用时顺延）并写日志（2026-09-29 调整）。
  - 环境变量 `UPSTREAM_BASE_URL` 重新定义为"仅测试用，覆盖当前供应商地址"。
  - 不支持降级回旧版本。
- schema 7 的顶层只写 `schema_version`、`selected_route_id`、`providers`、`routes`、`client_takeover`；旧版镜像选中通道的顶层字段（`upstream_base_url`、`listen_port` 等）不再写出，只在迁移时读取（2026-09-29 调整）。
- 全新安装：只建两条通道（Codex 18080、Claude Code 18081），不再预置 anyrouter.top / sotamodel.net 两个内置服务商；供应商由向导第 1 步或手动新增。没有配置文件但注册表里有 Rust 版配置时，仍按原规则一次性导入，并走同一套迁移。
- `ConfigService`：
  - 改为临时文件加替换的方式写入。只在迁移、删除供应商或 Key、接管之前备份，保留最近 5 份（删除与接管前的备份随 M3、M4 的对应功能一起加，2026-09-29 调整）。
  - 代理配置读取失败时，不再换成内置默认配置后落盘（会覆盖全部 Key），改为不写盘并提示。整个文件无法解析时同样处理：先备份原文件，本次运行只在内存里用内置配置，所有修改都不保存（2026-09-29 调整）。
  - 用 `RETRY_PROXY_CONFIG_JSON` 注入测试配置时，禁止写客户端配置。

## 9. 技术要点（供实现参考）

## 12. 验收标准

1. 迁移：以 dist 的真实配置结构迁移后，两条通道的 ID 不变，当日统计能继续累加；旧准备任务的来源映射正确。
2. 向导与接管：在临时的 `CLAUDE_CONFIG_DIR` / `CODEX_HOME` 下完成三步向导。
   - 原有地址和 Key 存成了供应商。
   - `settings.json`、`config.toml` 只有规定的键发生变化，备份存在。
   - Codex 的 `model_provider` 名称没变。
3. 直连恢复：退出软件后，客户端配置为当前 Key 的真实地址、密钥和模型；再次启动后自动接管。
4. 即时切换：用假上游 A、B 验证。
   - 切换后的下一次尝试打到 B，Key、模型、地址都正确。
   - 正在退避或等待生成的请求立即改投 B。
   - 已经开始输出的请求留在 A。
   - 「撤销」能切回 A。
5. 模型映射：
   - Claude 按角色映射；1M 头按目标角色增删；`count_tokens` 也会改写。
   - Codex 请求有效的手选模型时不改写。
6. 安全：
   - 不带本地口令的请求不会被注入 Key。
   - Host 非本机、或带 Origin 的请求被拒绝。
   - 日志和健康检查中不出现 Key 或口令。
7. 一键准备：
   - 一次勾选同一供应商的 3 个 Key，生成 3 项任务；供应商页状态同步。
   - 重启后，原本运行中的任务自动恢复。
   - 删除 Key 会联动停止并删除它的任务。
8. 余额：三种接口解析正确，自动识别能记住可用的接口；失败提示中不含 Key。
9. 界面：
   - 四个页面共用客户端切换；抽屉在窄窗口下占满内容区。
   - 托盘切换可用，窗口隐藏时也能切换。
10. 回归：现有约 418 个 xUnit 用例通过（因模型变化需要调整的，逐条说明）；三个验收脚本改写后全部通过。

|---|---|
