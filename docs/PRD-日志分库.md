# 日志按用途与日期保存

2026-10-11：用户确认运行日志也使用 SQLite，批准实施。配置数据库独立保存。

| 数据 | 文件 | 默认保留 |
|---|---|---|
| 运行日志 | `logs/runtime/yyyy-MM-dd.db` | 含今天 7 天，可设置 1–3650 天 |
| 请求诊断 | `logs/diagnostics/yyyy-MM-dd.db` | 含今天 7 天 |
| 请求统计 | `logs/statistics/yyyy-MM.db` | 永久 |

运行日志按事件发生的本机日期归档；诊断按请求开始日期归档，跨午夜仍写原日期。统计沿用现有跨日计数规则。客户端、来源与请求编号用于查询，不再增加文件层级。

运行日志保存原显示文本和完整请求编号、请求开始日期；新记录直接使用请求上下文，不从短编号反推身份。后台队列默认 4096 条，每批 256 条或 1 秒保存；队列溢出明确提示，数据库错误尝试写入 `runtime-emergency.log`（保留完整编号，5 MiB 阈值，3 个旧文件）。正常退出排空已接收的记录，最多等待 5 秒，超时在应急文本中提示。

旧 `data.db` 在一致性读取期间按日期复制，每批事务可重复执行。全部校验成功后写回旁路页，将旧库归档为 `data.db.migrated.bak`；失败保留旧库，阻止在未完成迁移的统计与诊断上继续写入。旧运行文本按文件内容与行序号去重导入，完成后改名为 `.migrated.bak`，中断警告不会被随后正常写入清除。归档备份不会被日期清理自动删除。通道在统计库尚无记录时，沿用当天恢复机制：从旧文本或归档、新运行库恢复统计，新记录使用完整编号，迁移副本不重复计入。

读取不存在的日期不创建数据库；每类数据只缓存最近写入的一个库。清理与读取、写入共用租约，等文件关闭后删除整组过期文件；外部占用时保留文件并提示失败。

## 界面布局

```text
+----------------------------------------------------------------+
| 客户端                  运行日志              自动滚动 / 打开目录 |
| 日期 [2026-10-11] [今天] [刷新] [导出筛选结果] [清空显示]         |
| 来源 [全部][通道代理][通道保活][一键准备][系统]                  |
| 级别 [全部][信息][警告][错误]   搜索 [...]   [仅当前客户端]      |
| 保存或清理异常提示                                              |
| 日志列表：每页 200 条；选中后可复制完整请求编号、查看诊断        |
| [较新一页]             第 1 / N 页                [较早一页]    |
+----------------------------------------------------------------+
```

延续现有 WPF 主题资源、MiSans/Consolas 字体、筛选按钮与深浅主题；窄窗口工具栏换行。沿用现有交互反馈，不增加入场动画。加载时禁用翻页；筛选变化取消旧查询，离开页面停止刷新；翻页固定查询快照，实时追加不挤动正在浏览的历史页。导出当前日期全部筛选结果，以文本保存，包含完整请求编号。

设置页增加运行日志保留天数与“清理过期日志”，清理显示结果。配置保存成功后才启用新保留天数；启动读取配置前暂停清理，旧配置或非法保留天数使用默认 7 天。清空显示、导出和翻页在所选日期尚未加载时不可操作；实时刷新尽量保留所选请求。
